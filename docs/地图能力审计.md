## 三、建议的决策路径：用一个「10 分钟实验」代替争论

1. **你操作**：DevEco 登录华为账号 → 项目结构 → Signing Configs →
   `Enable open capabilities` → 勾 `Map Kit` → OK → Apply（会自动重签 Profile）
2. **我操作**：在 `MapView.ets` 加一个**最小** `MapComponent`（只放武汉中心点 + 1 个 Marker，
   不接任何业务数据）
3. **装到模拟器看结果**：
   - 出图 ⇒ **走 A**，再往上接业务
   - 白屏 / 报错 ⇒ **立刻转 B**，不要在这条路上耗超过半天

理由：A 的上限（原生组件、答辩加分）明显更高，而**验证成本极低**。
反过来「先做 B 再改 A」是双份工。

⚠️ 已知的时间风险：FAQ 提到「开通地图服务后最多需要等待 24 小时才能生效」，但该说明挂在
`HarmonyOS 5.0.2(14) 及以前版本` 的语境下，我们 compatibleSdk 是 `6.1.1(24)`，理论不受影响。
**若开通后立刻白屏，隔天再试一次**，别当晚就判死刑。

## 四、还要先定的设计问题：地点数据从哪来

现有数据模型**没有经纬度、也没有详细地址**：

```ts
export interface Application {
  id: number;
  company: string;
  position: string;
  city: string;        // 默认 '武汉'
  channel: string;
  status: string;
  ...
}
```

`EventNode`（笔试 / 面试 / 截止）同样只有 `title`，没有地址 ——
而「我要去的地点」其实主要是**面试地点**，不是公司注册地。

三个来源，建议 2 + 3 组合：

1. **用户手填详细地址** —— 要多加录入 UI，且用户大概率懒得填
2. **实时地理编码** —— 调地图服务把公司名解析成坐标；依赖网络 + key，且公司名匹配常不准
3. **内置「武汉 IT 公司坐标种子库」** —— 用户只输公司名，本地模糊匹配直接落点
   ⇒ **零网络、零 key、瞬时、答辩可复现**，最稳

## 五、已核实并排除（答辩被追问时照这条答）

| 能力 | 判定 | 原因 |
| --- | --- | --- |
| Map Kit「我的位置」 | 弃 | 模拟器不支持（无 GPS） |
| Map Kit「通过地图应用导航」 | 弃 | 模拟器不支持；且模拟器内无花瓣地图 App |
| Map Kit「离线地图」 | 弃 | 模拟器不支持 |
| Map Kit on OpenHarmony | 弃 | 官方明确「当前不支持 OpenHarmony」 |
| 把地图 MCP 装进 App | 弃 | **MCP 不是 App 能调用的东西**，见下 |

### 关于「接入各种地图 App 的 MCP」

**MCP（Model Context Protocol）是 AI 助手在对话 / 开发时调用的工具协议，运行在助手这一侧。
鸿蒙 App 在运行时没有任何途径去调用一个 MCP Server。**

App 想用地图，只有两条路：

- **地图 SDK** —— 华为 Map Kit（`MapComponent`）
- **HTTP API** —— 地图服务商的 Web 服务（地理编码 / 地点搜索 / 静态图）

MCP 在这里的**真实用途**是：在**开发期**由助手把「公司名 → 经纬度」批量跑出来，
直接生成上面第四节的**种子库**，作为静态数据写进工程。
这件事有价值 —— 但它发生在「准备数据」这一步，**不是「App 自己会看地图」**。
