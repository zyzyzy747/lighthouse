# STORY.md · 灯塔 Lighthouse 作品介绍

## ① 用户意图对齐

**目标受众**：2026 第二届「光谷杯」鸿蒙生态创新大赛初赛评委（线上材料评审）。评委构成里既有鸿蒙技术专家，也有政府领导与产业/投资侧评委——技术深度与政策叙事必须同时成立。

**核心目标**：讲完之后，评委要记住三件事——
1. 「桌面服务卡片是主入口」——这是鸿蒙原生最直接的证据；
2. 「能力雷达把弥散焦虑收敛成一张补强清单」——这是市面上没人做过的创新点；
3. 「一屏三形态：手机随手记 / 平板看全局 / 折叠屏作战」——这是一多部署的真实价值。
最终诉求：在创新性 50 分上拿高分，并让「前景评估」20 分有政策抓手可依。

**PPT 长度**：16 页（章节扉页 4 页 + 封面/目录/团队介绍/结束 4 页 + 内容 8 页）。Hero 页 4 页（25.0%）—— 团队介绍页虽有 104px 巨型数字，但整页是双栏信息结构、留白 22%，按「围绕单一焦点」的定义归 supporting。

**视觉调性**：深海科技 · 单色系统 · 数据驱动 · 克制。与应用 UI 同源（深海蓝底 + 主蓝 + 琥珀强调），让 PPT、实机截图、演示视频三者视觉一致——评委在视频里看到的界面必须和 PPT 上是同一套东西。

**内容边界**：
- **必讲**：三大痛点、真实数据与政策抓手、桌面卡片作为主入口、能力雷达的算法口径、一多三形态、鸿蒙能力矩阵、光谷产业结合。
- **不讲**：12 天排期表、风险清单、答辩预演四问、实况窗的取舍过程（这些是内部工作文档的内容，放在 PPT 里只稀释重点）。
- **禁碰**：未在工程里验证过的 API 名称；把演示数据说成调研结论；任何无法核验的数字。

**目录↔章节扉页契约**：P03 目录声明 4 个章节 → 全篇有且仅有 4 个 `type: section` 扉页（P04 / P07 / P11 / P14），编号 01..04 连续，标题与目录条目**逐字一致**。

**Hero 页定位**：P01 封面、P06 数据冲击、P09 桌面即首页、P16 结束页 → 4 页 / 16 页 = 25.0%，落在 20–30% 区间。任意两个 Hero 之间至少隔 1 个 Supporting（P01→P06 之间 P02/P03 supporting、P04 transition、P05 supporting；P06→P09 之间 P07 transition、P08 supporting；P09→P16 之间 P10–P15 supporting/transition）。

**rhythm 曲线**：
P01 peak → P02 valley（团队介绍）→ P03 valley（目录）→ P04 transition → P05 valley → P06 peak → P07 transition → P08 valley → P09 peak → P10 valley → P11 transition → P12 valley → P13 valley → P14 transition → P15 valley → P16 peak。
无连续 ≥ 3 页 valley（P02+P03 是最长的一段，2 页）；章节切换处（P04/P07/P11/P14）均为 transition。

**非对称版式预算**：16 页中需 ≥ 6 页非对称。本稿非对称 9 页（P02 非对称双栏 / P05 非对称双栏 / P06 巨型数字+洞察 / P08 左标题+右内容 / P09 左大图+右侧文字 / P10 上大图+下方卡片 / P12 非对称双栏 / P13 非对称双栏 / P15 左标题+右内容）= 56%。
**对称版式预算**：结构性页面（P04/P07/P11/P14 章节扉页、P16 结束页）按 §1「封面 / 章节过渡 / 结束页允许自定义版式」处理，不计入对称预算；**内容页不使用 `N卡片横排`**。
