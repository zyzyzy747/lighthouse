「不是手机上有 AI，而是 AI 决定了这台手机在没网的时候还能不能干活。」 这份文档回答三件事：DeepSeek 能不能接、接在哪一层、怎么接才不会被评委当成套壳
01

先回答：DeepSeek 能不能接

已实测

能。而且我刚在这台机器上实测过。直接 POST api.deepseek.com/chat/completions，无密钥时返回 401 Authentication Fails (governor)，耗时 0.67 秒 —— 说明网络路径通畅，只差一个 key 的事。

但有三件事必须先改口径，否则会踩坑：

⚠ 坑一：模型名已经变了，网上教程基本全是错的

旧的 deepseek-chat 和 deepseek-reasoner 两个别名已于 2026 年 7 月 24 日退役，继续调用会直接请求失败。现在必须用 deepseek-flash。另有一个更隐蔽的：中间名 deepseek-v4-flash 虽然仍可调用，但背后的模型已下线，请求会被静默路由到 V4.1-Flash —— 能跑，但你不知道自己在跑什么。

坑二：要联网，所以演示有断网风险

这是双刃剑。接上云端能力产品更强，但演示现场如果网络抖动，功能就哑了。缓解办法不是「祈祷网络好」，是架构上做降级（见第 03 节）。

坑三：密钥不能硬编码

hap 包内的 abc 字节码可被逆向，明文写在代码里的 key 一定会泄露。如果你用的是自己的主账号，被盗刷是真金白银的损失。处理办法见第 06 节。

02

核心判断：不要让 DeepSeek 当主角

这条比技术选型更重要

你问「加上 AI 竞争力会不会很大」。我的判断是：方向对，但如果只是「接了个大模型」，反而是负分。纯接 API 有三个死法：

  • 断网即死 —— 评委问一句「没网能用吗」，答不上来就完了。
  • 被当成套壳 —— 「你不就是调了个 DeepSeek 吗，创新点在哪？」这是最可能的追问。
  • 没有壁垒 —— 任何一个参赛队今天下午都能做出同样的东西。

真正的差异化不在云端，在端侧。我把鸿蒙能用的 AI 能力逐个核实了一遍：

能力Kit模拟器审批门槛结论
语音听写（离线模型） Core Speech Kit ✅ 6.0.0 起支持 无需审批 用
自然语言理解（分词/实体） Natural Language Kit ❌ 不支持 无需审批 弃
文本识别 OCR Core Vision Kit ❌ 不支持 无需审批 弃
意图框架 Intents Kit 受限 需 AGC 审批 + 上架 弃
实况窗 Live View Kit 受限 5 工作日审批 已砍

这张表里唯一亮着的绿灯，价值比云端高

语音听写是唯一能在模拟器上跑通的鸿蒙端侧 AI 能力，而它跑的是离线模型 —— 不需要网络、不需要额度、数据不出设备。这正好戳中我们方案的核心场景：挤地铁去面试的应届生、车间里信号只有一格的技术员。演示视频里「对着手机说一句『今天投了字节跳动的 Java 后端』，一秒变成一条结构化记录」，这个镜头的说服力，远超让评委看一个聊天框。

03

端云双模架构

AI 放在哪一层，决定它值不值钱
L1 · 端侧
永远可用 · 零成本 · 零审批 · 数据不出设备 ① 语音速记：Core Speech Kit 离线听写，「说一句记一条」 ② 本地解析引擎：正则 + 词典，从口语里抽出公司 / 岗位 / 地点 / 日期 ③ 全部统计计算：漏斗、时间轴、雷达图渲染、已有分数展示
L2 · 云侧
DeepSeek · 只在用户开启时调用 · 可一键关闭 只做三件「非大模型不可」的事：面试复盘语义归因、JD 技能差距分析、面试官追问训练 共同特征：输入是非结构化的人类语言，输出要落进数据模型
L3 · 降级
网络不可达 / 密钥无效 / 用户关闭 → 自动回落 L1 UI 明示「本地模式」，并解释哪些功能暂不可用、为什么 关键：降级不是崩溃，是设计。评审看到这段提示会明白这一点

答辩时可以直接说的一句话

「能端侧的一律端侧，只有非结构化的人类语言才上云。」

DeepSeek 接入规范

参数与成本，2026-09-18 核实

端点与模型

Authorization: Bearer sk-xxxxxxxx
Content-Type: application/json

{
  "model": "deepseek-flash",
  "messages": [ {"role":"system","content":"…"}, {"role":"user","content":"…"} ],
  "stream": false,
  "temperature": 0.2,
  "max_tokens": 1500,
  "response_format": { "type": "json_object" },
  "thinking": { "type": "disabled" }
}

当前价目与成本估算

DeepSeek 自 2026-08-17 起启用峰谷定价，高峰时段为周一至周五 9:00–12:00 与 14:00–18:00，其余时段为空闲，空闲价是高峰的一半。

模型输入（缓存命中）输入（未命中）输出上下文并发
deepseek-flash 0.02 / 0.04 元 1 / 2 元 4 / 8 元 1M2500
deepseek-v4-pro 0.15 / 0.30 元 4.5 / 9 元 13.5 / 27 元 1M500

单位：元 / 百万 tokens，格式为「空闲 / 高峰」。两个模型都支持 JSON 输出与 Function Calling。

成本低到可以忽略

一次面试复盘分析，输入约 2000 token（含 system prompt 与回忆原文）、输出约 1000 token。用 deepseek-flash 按高峰价计算：

2000 ÷ 1e6 × 2 + 1000 ÷ 1e6 × 8 = 0.004 + 0.008 = 0.012 元

约 1.2 分钱一次。就算演示期间反复跑 200 次，总成本 2.4 元。整个比赛周期花的钱不够买一瓶水 —— 所以「成本」不是这个方案要考虑的问题，「质量」和「可信度」才是。

三个必须调对的参数

参数设置为什么
response_format json_object 不设的话模型会返回带说明文字和 ```json 包裹的内容，直接 JSON.parse 必崩。这是新手第一大坑，实测踩中率极高。
thinking disabled 官方默认开启思考模式。结构化打分任务不需要长链推理，关掉后响应更快、更便宜、输出更稳定。若要最强归因能力，改 enabled 或换 deepseek-v4-pro。
temperature 0.2 打分必须可复现。同一份面试回忆跑两次，分数如果差 20 分，雷达图就失去意义了。低温度是「可比较」的前提。

⚠ 一个待实测的兼容性问题

「思考模式」与「JSON 输出」能否同时开启，官方文档没有明确说明（只提到 FIM 补全仅支持非思考模式）。我们的方案里两者是分开的 —— 结构化任务用 disabled，所以不受影响。但第一次跑通时请顺手测一下 enabled + json_object，记下结果。这是答辩时可能被技术专家问到的一个点。

05

三个 Prompt 场景

产品的灵魂在这三页里

「加 AI」的正确姿势不是加一个聊天框，而是想清楚大模型在哪一步不可替代。我只找到三处。完整 Prompt 已写进代码（PromptLibrary.ets），这里说设计原则。

功能输入 → 输出为什么必须用 LLM
复盘 → 能力雷达 一段口语化的面试回忆 → 5 个维度的分数 + 证据句 + 补强建议 把情绪化叙述（「问的都不会，感觉凉了」）映射成可量化指标，规则引擎做不到
JD → 技能差距 招聘 JD 原文 + 我的技能底牌 → 必须项/加分项逐条标匹配状态 + 备考清单 JD 写法千变万化，关键词匹配抓不到「熟悉高并发场景下的数据一致性」= 分布式事务 + 锁
追问教练 雷达图上最弱的两个维度 → 面试官连问三轮，每轮指出具体漏洞 需要理解上下文并针对性地挑刺，是典型的生成式任务

让「AI 打分」不变成「AI 算命」的三条铁律

这三条不是随便定的，是这类产品翻车的三个主要原因，每一条都写死在 prompt 里：

  1. 判分标准必须写进 prompt。只说「给 0–100 分」，模型会随便给；给出分档（0–40 答错 / 41–60 答不完整 / 61–80 细节含糊 / 81–100 能延伸），分数才有可比性。
  2. 必须显式禁止编造。不写这条，模型会为了「把雷达图填满」凭空给你补出一个六边形战士 —— 这是最常见的幻觉形式，因为它看起来「很合理」。我们的规则是：回忆里没提到的维度，score 记 0 并注明「本次面试未涉及」。
  3. 证据必须引用原文。每个分数都要给出对应的原话片段，禁止自己造句。这条让用户能自己核对分数是否离谱，也让答辩时你能解释「分数是怎么来的」。

这三条同时就是答辩的标准答案

被问「你怎么保证 AI 不胡说」—— 你不需要讲技术原理，只需要把上面三条念出来，再说一句：「我们做了一个可复现的评估器，不是一个问答机器人。」

06

密钥策略

这里出事是要花钱的
方案安全性演示便利答辩观感
硬编码进代码 必然泄露 最省事 若被扒出或质疑，是工程素养扣分项
内置限额 key + 设置页 BYOK 可控 最省事 可讲成隐私设计加分项
自建代理转发 最好 多一层依赖 但评委可能问「这还算鸿蒙应用吗」，且断网即死

推荐做法：内置限额 key 兜底 + 设置页支持用户自带

  • 单独申请一个 key，只充 20 元，在 DeepSeek 控制台设好消费上限。绝对不要用主账号。
  • 设置页提供密钥输入框，用户填了就覆盖内置的。密钥只存本机偏好库，不上传任何服务器。
  • 答辩口径：「我们采用 BYOK，用户自带密钥，密钥不经过我们的服务器。」—— 这句话把一个安全妥协讲成了隐私设计。

为什么不推荐给学生队做代理

自建一个转发函数（云函数 / Worker）技术上只要半小时，但它引入了一个外部依赖：演示现场如果那个函数挂了或没配好，整个 AI 功能哑掉。而它的收益（防密钥泄露）对一个 12 天工期的参赛作品来说并不关键 —— 用限额 key 把最坏损失锁在 20 元以内，更划算。把省下的时间投到演示视频上，回报率高得多。

08

答辩预演：AI 相关必问四题

背下来

Q1：你们这个 AI，是不是就是套壳 DeepSeek？

不是，从三个层面都不是：

  • 架构上：能离线的一律端侧 —— 语音速记用鸿蒙 Core Speech Kit 的离线模型，投递解析用本地规则引擎。只有「把非结构化的人类语言变成结构化指标」这一步才上云。
  • 产品上：模型输出不直接给用户看，而是落进数据模型，变成可追踪、可对比的量化指标。下周你再复盘一次，雷达图会告诉你有没有进步 —— 这是聊天框给不了的。
  • 工程上：判分标准写死在 prompt 里（分档 + 证据引用 + 未涉及记 0），保证同一份输入得到稳定可比的结果。我们做的是可复现的评估器。

Q2：AI 给的分数准吗？

不追求绝对准确，追求相对可比。它衡量的是「你在表达里暴露了多少漏洞」，不是「你的真实技术水平」。这个定位我们写进了产品说明，也写进了 prompt。用户能看到每个分数对应的原话证据，可以自己判断是否离谱。

Q3：网络断了怎么办？

自动降级到本地引擎，界面上会明示「本地模式」并说明哪些功能暂不可用。这不是兜底，这是设计 —— 我们的目标用户是挤地铁去面试的应届生，地铁里就是没网；是车间里盯着设备的技术员，车间里信号只有一格。如果一个求职工具必须联网才能用，那它就不该叫「随身助手」。

Q4：数据安全怎么保证？

三层：简历、薪资、公司名等敏感字段本地存储，不上传；送到模型的只有脱敏后的复盘文本片段；设置页提供「纯离线模式」开关，一键关闭所有云端调用。

合规：主动说，别等被问

调用已备案的大模型服务（DeepSeek）属于合规路径。产品不上架、不面向社会公众提供生成式服务，仅作为工具类应用的辅助功能。在 PPT 里主动写这一句 —— 评委看到会知道你想过这个问题，这是加分项，不是减分项。

09

排期怎么变 & 风险

AI 插在哪一天

原排期里 D6–D8 是「复盘 + 雷达图」，AI 接入是 D8–D9 的活。但有一条硬要求：

D1 就把 DeepSeek 跑通，别等到 D8

在工程里写一个最小的连通性测试页（一个按钮、一次请求、把响应原文打到日志），今天就该做。要验证四件事：① 模拟器能不能访问外网；② 宿主机的系统代理会不会干扰；③ 密钥是否有效；④ thinking:disabled 与 json_object 能否并用。这几件事任何一件出问题，都会改变后面 10 天的设计。等 D8 才发现，就来不及了。

风险等级应对
密钥泄露被刷 中 单独申请 + 控制台设限额 + 设置页支持 BYOK。最坏损失锁死在 20 元。
演示现场断网 中 三层降级已设计好；演示视频用录屏，不要现场联网跑。
ArkTS 严格模式编译报错 中 代码未编译验证。首次编译报错贴给我，我按报错逐处修。
模型幻觉编造能力项 中 prompt 三条铁律（分档标准 / 未涉及记 0 / 证据引用）已内置。
思考模式与 JSON 输出兼容性未知 低 方案里两者分开使用，不受影响。首测时顺手记录结论即可。
